## 二、P0 救命核心

### 1. 急救手册

#### 1.1 功能描述
提供常见户外急救知识的快速查阅，包含症状识别、操作步骤、禁忌事项。

#### 1.2 用户故事
> **作为** 户外爱好者
> **当** 我在野外遇到受伤或突发疾病
> **我想要** 快速查找急救方法
> **以便于** 在救援到达前进行正确的处理

#### 1.3 功能规格

| 项 | 说明 |
|---|---|
| **名称** | 急救手册 |
| **入口** | 主界面"急救" / 主页急救卡片 |
| **数据量** | MVP 8 条核心 → 完整 200+ 条 |
| **分类** | 急症优先 / 创伤 / 环境 / 中毒 / 应急 |
| **紧急度** | 5 级（危急/高/中/低/知识）|
| **每条内容** | 标题、症状、关键步骤、详细步骤、禁忌、来源、审核医师 |
| **搜索** | 支持关键词 |
| **筛选** | 按分类 / 紧急度 |

#### 1.4 验收标准
- [ ] 能列出所有急救条目（按分类）
- [ ] 能按紧急度筛选
- [ ] 详情页有完整步骤
- [ ] 必填字段缺失时显示警告
- [ ] 搜索响应 < 200ms
- [ ] 紧急度 >= 4 的条目用红色标识

#### 1.5 边界情况
- 搜索无结果时显示"暂无相关急救知识"
- 急救条目缺失字段时显示降级界面
- 内容审核人信息必填

### 3. SOS 紧急求救

#### 3.1 功能描述
长按 3 秒触发 SOS，自动拨打 120 并通知紧急联系人。

#### 3.2 用户故事
> **作为** 在户外遇到紧急情况的受伤者
> **当** 我无法正常使用手机
> **我想要** 通过简单操作触发求救
> **以便于** 救援人员尽快到达

#### 3.3 功能规格

| 项 | 说明 |
|---|---|
| **入口** | 主界面底部 SOS 按钮（始终可见）|
| **触发** | 长按 3 秒（防误触）|
| **触发后动作** | 拨打 120 / 启动 GPS / 1.5s 后发短信 |
| **短信内容** | 位置 + 时间 + 求助信息 |
| **取消** | 长按期间松开 / SOS 状态页取消 |
| **历史** | 记录每次触发（本地）|

#### 3.4 验收标准
- [ ] 长按 3 秒准确触发
- [ ] 倒计时清晰可见
- [ ] 拨打 120 成功
- [ ] 短信发送给所有紧急联系人
- [ ] 短信包含准确 GPS 坐标
- [ ] 短信内容格式正确
- [ ] 取消操作正常
- [ ] GPS 权限被拒时降级
- [ ] 无网络时降级（仅拨打电话）

#### 3.5 关键约束
- 拨打 120 **必须真的能拨出**（不能弹虚假提示）
- 短信必须包含求救信息
- GPS 坐标精度应 < 50m
- **精度读数只报硬件自己量出来的那个 ±**（2026-10-26 #129）：静止时可以把最近几帧按 1/σ²
  加权求均值来定位置，但**报出去的是池内最好那一帧自量的 σ，不是理论 σ/√N**；未知就整行
  不显示，不写 `±0 m`、不写 `0.0 米`、不写 `-1`。原口径是"精度应 < 50 m"，那是**验收阈值**，
  不是界面可以拿来凑数的默认值。

### 6. 拍照 AI 识别

#### 6.1 功能描述
拍照识别动植物，支持本地（NCNN）和云端两种模式，自动降级。

#### 6.2 用户故事
> **作为** 户外徒步时遇到不认识的动植物
> **当** 我想了解这是什么
> **我想要** 拍照即可识别
> **以便于** 快速知道是否有危险、是否可食

#### 6.3 功能规格

| 项 | 说明 |
|---|---|
| **入口** | 主界面"拍照识别" |
| **类别** | 植物 / 动物 / 蛇 / 蘑菇 / 昆虫 |
| **识别方式** | 拍照 / 相册 / 实时相机 |
| **本地模式** | NCNN 端侧推理（< 200ms）|
| **云端模式** | 上传图片到 API（< 2s）|
| **自动模式** | 在线云端，离线本地 |
| **结果** | Top-5 候选 + 置信度 |
| **关联** | 识别后可跳转到物种详情 |

#### 6.4 验收标准
- [ ] 能选择识别类别
- [ ] 相机预览流畅
- [ ] 拍照保存到本地
- [ ] 从相册选择图片
- [ ] 本地推理 < 1s
- [ ] 云端推理 < 3s
- [ ] 网络失败时降级本地
- [ ] Top-5 候选展示
- [ ] 低置信度有警告
- [ ] 识别记录自动保存

#### 6.5 性能要求
- 端侧推理时间 < 200ms（中端机）
- 应用启动 < 3s
- 内存占用 < 300MB
