# 文档同步规范

> **项目级强制规则**: 任何代码变更(新增功能/重构/修复漏洞/性能优化)后,必须同步梳理文档。
> 制定日期: 2026-08-26
> 适用范围: 全部开发者

---

## 一、规则

每次实现/改进/删除功能,**必须**执行:

### 1. 代码改完第一步(改前思考)
在动手前,先回答:
- 这会改变哪些 API?
- 涉及哪些数据文件?
- 影响哪些 QML 页面?
- 影响哪些用户可见行为?

### 2. 代码改完第二步(改后必做)

| 类别 | 必更新文档 | 触发条件 |
|---|---|---|
| **新增/删除/重命名** API | `08-索引与概念/全代码索引.md` 第十五节 | 任何 C++ public 方法变更 |
| **新增/删除数据** | `10-需求清单/需求清单与实现状态.md` 第 9 节(数据维度) | 数据条数/字段变化 |
| **新增/删除/重命名** QML 页面 | `10-需求清单/需求清单与实现状态.md` 第 11 节(UI 页面) | 新页面/入口 |
| **修复 bug** | `代码审查与测试报告.md` 修复记录 | 修任何 P0/P1 |
| **架构变更** | `01-方案设计/` 下的相关文档 | 服务重组/接口大改 |
| **构建/部署变更** | `07-部署与发布/Docker构建APK手册.md` | Dockerfile / 构建脚本改 |
| **统计数字变化**(路线/物种/装备条数) | `00-文档总览.md` 末段项目状态 | 数据扩展后 |
| **数据格式变化** | `10-需求清单/需求清单与实现状态.md` 关键决策 | JSON 字段增删 |
| **依赖变化** | `05-工程规范/工程规范手册.md` | Qt 版本/库变化 |

### 3. 文档同步自检清单

每次改完代码,在 commit 前过一遍:
- [ ] 是否改了 `assets/data/*.json`? → 同步 `10-需求清单` 第 9 节
- [ ] 是否加了新 `Q_INVOKABLE`? → 同步 `全代码索引` 第十五节
- [ ] 是否加了新 QML Page? → 同步 `需求清单` 第 11 节
- [ ] 是否改了 CMakeLists? → 同步 `Docker构建APK手册`
- [ ] 是否改了 Dockerfile? → 同步 `Docker构建APK手册`
- [ ] 是否修了 P0/P1 bug? → 同步 `代码审查与测试报告` 修复记录
- [ ] 数字变化(条数/百分比)? → 同步 `00-文档总览` 末段

## 二、文档审查自动化

**工具**: `doc/05-工程规范/doc_check.js`(Node.js 脚本,检测 API 数量变化)

**辅助工具**: `doc/deep_audit.js`(代码漏洞扫描,P0/P1/P2 分类)

**功能**: 扫描 `src/` 改动,自动列出可能需要同步的文档。

```bash
# 在 app/ 目录下
node doc/05-工程规范/doc_check.js
node doc/deep_audit.js
```

输出示例:
```
[doc_check] 扫到 src/routes/RouteService.cpp 改动 (Q_INVOKABLE 数量 28 → 30)
  需更新: doc/08-索引与概念/全代码索引.md (第十五节)
  需更新: doc/10-需求清单/需求清单与实现状态.md (第 5 节)

[doc_check] 扫到 src/core/Logger.cpp 改动
  需更新: doc/05-工程规范/工程规范手册.md (日志规范)
  需更新: doc/10-需求清单/需求清单与实现状态.md (第 9 节 系统功能)
```

## 三、文档角色与维护者

| 文档 | 角色 | 更新时机 |
|---|---|---|
| `00-文档总览.md` | **入口** | 数据/状态变化时 |
| `01-方案设计/*.md` | 设计思路 | 架构大改时 |
| `02-实施规划/*.md` | 计划 | 新阶段启动时 |
| `03-API设计/API设计文档.md` | **API 权威** | API 变更时 |
| `04-数据库/数据库设计文档.md` | **表结构权威** | 表变更时 |
| `05-工程规范/*.md` | 规范 | 规范变更时 |
| `06-功能与测试/完整功能清单.md` | 功能清单 | 功能增删时 |
| `06-功能与测试/测试用例文档.md` | 测试清单 | 测试变更时 |
| `07-部署与发布/Docker构建APK手册.md` | **构建权威** | Dockerfile/脚本变更时 |
| `08-索引与概念/全代码索引.md` | **代码地图** | API/类变更时 |
| `09-讨论记录/*.md` | 历史归档 | 决策后 |
| `10-需求清单/需求清单与实现状态.md` | **项目宪法** | 任何变更后 |
| `代码审查与测试报告.md` | 修复记录 | P0/P1 修复后 |

---

## 四、文档版本控制

- 所有文档头部保留**最后更新日期**
- 重大变更写到对应文档的 **change_log** 或追加到末尾(注明日期)
- `10-需求清单/需求清单与实现状态.md` 的"最后更新"行**必改**

---

## 五、违规处理

如果 PR/commit 缺少文档同步:
- code review 必须拒绝
- 提交者需在 24h 内补齐文档

---

## 六、紧急更新流程(已修 P0/P1 漏洞时)

1. 立即修复代码
2. 立即更新 `代码审查与测试报告.md` 修复记录
3. 立即更新 `需求清单` 中相关需求的状态
4. 24h 内同步其他文档

---

**维护**: 本规范由项目负责人维护,任何变更需团队评审。
