# Service 接口命名规范

> 本文档是 **工程规范手册 §1.1.x** 的补充章节,定义 Service 接口层(Q_INVOKABLE + QML 调用端)的统一命名。
> 制定日期: 2026-09-20 / 适用版本: v0.0.1 起 / 状态: 强制
> 配套: `Result<T>` + `ServiceError` + `QmlResultBridge` (Phase 2 起); `DbHelper` (Phase 2 起); `ServiceBase` (Phase L2 起)

---

## 零、底层强约定 (适用所有 .h/.cpp)

> 2026-09-21 L1 v0.3 新增。本节是命名规范的"宪法",违反者 PR 必须驳回。

### 0.1 类名前缀

| 后缀 | 语义 | 典型示例 | 反例 (禁用) |
|---|---|---|---|
| `*Service` | 业务服务 (QML 通过 context property 访问) | `EquipmentService` / `KnotService` | ~~`EquipmentEngine`~~ (Phase I-3 已统一) |
| `*Repository` | 数据访问层 (CRUD 模板) | `SpeciesLocationRepository` (L4 改名) | ~~`DbHelper` 等通用工具~~ |
| `*Strategy` | 策略模式 (算法族) | `RuleConditionStrategy` | — |
| `*Factory` | 工厂模式 (创建 strategy / widget) | `RuleConditionFactory` / `SpeciesServiceRegistry` | — |
| `*Base` | 抽象基类 (含纯虚函数) | `ServiceBase` (L2 新增) | ~~`SpeciesServiceBase`~~ (L1 已删, 是反面教材) |
| `*Helper` | 静态工具类 | `AssetLoader` / `PathService` | — |
| `*Registry` | 注册表 (单例, 服务容器) | `ServiceRegistry` / `SpeciesServiceRegistry` | — |
| `*Engine` | **禁用** | — | 全部改 `*Service` |
| `*Manager` | **禁用** | — | 改 `*Service` 或 `*Registry` |

### 0.2 公共方法命名 (C++ `Q_INVOKABLE` + 普通 public)

| 类别 | 命名 | 说明 | 反例 → 正例 |
|---|---|---|---|
| 取单条 | `getById(QString id)` | 按 id 取一条数据 | `getItem` / `getChecklist` / `getPhoto` / `getTrack` / `getEntry` → **`getById`** (Phase 4 已统一) |
| 取全部 | `getAll()` | 返回所有数据 | `getAllEntries` / `getAllItems` / `getAllPhotos` → **`getAll`** |
| 按月取 | `getByMonth(int month)` | 按月份过滤 (1-12) | `getBySeason(int)` → **`getByMonth`** (Phase 4 已统一) |
| 按类别 | `getByCategory(QString cat)` | 按业务类别过滤 | — |
| 按地区 | `getByProvince(QString p)` | 按省/地区过滤 | — |
| 搜索 | `search(QString kw)` | 关键字搜索 | — |
| 删除单条 | `deleteXxx(QString id)` | 删一条 | `removeXxx` / `deleteRecord` / `deleteByEntity` → **`deleteXxx`** (Phase 4 已统一) |
| 删除多条 | `deleteXxxBatch(QStringList ids)` | 批量删 | — |
| 收藏 (3 件套) | `addFavorite(id)` / `deleteFavorite(id)` / `isFavorite(id)` / `getFavorites()` | 强制统一 | — |
| 访问计数 | `incrementVisitCount(id)` | 详情页 +1 | — |
| 谓词 | `isXxx()` / `hasXxx()` / `canXxx()` | 返回 bool | — |
| 创建返回 id | `startXxx()` / `createXxx()` / `importXxx()` | 返回 QString 非空 = id | — |

### 0.3 成员变量

| 类别 | 命名 | 说明 |
|---|---|---|
| 类成员 | `m_xxx` | Qt 风格, 无例外 |
| 局部变量 | `camelCase` | 无前缀 |
| 常量 | `kXxx` | 类级别 `static constexpr int kCurrentSchemaVersion = 2;` |
| 静态成员 | `s_xxx` (极少用) | — |

### 0.4 Q_INVOKABLE 划分

- **加 `Q_INVOKABLE`**:**仅** 给 QML 调用的方法
- **不加**:C++ 内部调用 (e.g. `loadInitialData` / `ensureSchema` / `parseEntity`)
- 原则:不为了"看起来重要"加 `Q_INVOKABLE`, 这会让 QML 端暴露过多 API

### 0.5 枚举前缀

| 类型 | 命名 | 示例 |
|---|---|---|
| 业务枚举 | `*Level` / `*Type` / `*Mode` | `AltitudeLevel::L0` / `DangerLevel::L4` / `LoadMode::Lazy` |
| 字段 enum class | `Name` / `Status` (无后缀, 简洁) | `Database::Name::Species` / `RecordStatus::Active` |
| 禁用 | `E_xxx` (无意义前缀) / `XXX_xxx` (C 风格宏) | — |

### 0.6 命名空间

- **所有代码** 必须在 `namespace outdoor { ... }` 内
- **禁用** anonymous namespace (`namespace { ... }`), 改用文件作用域 static
- 例外: `Logger::instance()` / `CommonOptions` 单例模式见 §七

### 0.7 文件一一对应

| 规则 | 示例 |
|---|---|
| 一个类一个文件 (`.h` + `.cpp`) | `EquipmentService.h` / `EquipmentService.cpp` |
| header-only 类 (e.g. `ServiceBase` 模板 / `IRepository<T>`) | 单 `.h` 文件, 不强求 `.cpp` |
| 工具类 | 一个类一个文件, 避免 `utils.cpp` 堆叠 |
| 类名 = 文件名 (PascalCase) | `class KnotService` → `KnotService.h` |

### 0.8 Result 返回 (写操作)

- C++ 内部写操作必须 `Result<T>` (T = bool/对象)
- Q_INVOKABLE 写操作:Phase 5 切 `QVariantMap` (通过 QmlResultBridge 自动转)
- bool 仅 `is*/has*/can*` 谓词使用

### 0.9 测试类

| 规则 | 示例 |
|---|---|
| 测试类名 = `Test<Xxx>` + `Service` (或 `Engine`) | `TestEquipmentService` (Phase I-3 已统一) |
| 文件名 = `test_<snake_case>.cpp` | `test_equipment_service.cpp` |
| 一个测试类一个文件 | — |

## 一、Service 方法命名 (C++ `Q_INVOKABLE`)

### 1.1 基础 CRUD

| 类别 | 命名 | 说明 | 反例 → 正例 |
|---|---|---|---|
| 取单条 | `getById(QString id)` | 按 id 取一条数据 | `getItem` / `getChecklist` / `getPhoto` / `getTrack` / `getEntry` → **`getById`** |
| 取全部 | `getAll()` | 返回所有数据 | `getAllEntries` / `getAllItems` / `getAllPhotos` → **`getAll`** |
| 按月取 | `getByMonth(int month)` | 按月份过滤 (1-12) | `getBySeason(int)` → **`getByMonth`** |
| 按类别 | `getByCategory(QString cat)` | 按业务类别过滤 | — |
| 按地区 | `getByProvince(QString p)` | 按省/地区过滤 | — |
| 搜素 | `search(QString kw)` | 关键字搜素 | — |
| 删除单条 | `deleteXxx(QString id)` | 删一条 | `removeXxx` / `deleteRecord` / `deleteByEntity` → **`deleteXxx`** |
| 删除多条 | `deleteXxxBatch(QStringList ids)` | 批量删 | `removeAllSelectedItems` → **`deleteXxxBatch`** |

### 1.2 业务组合

| 类别 | 命名 | 说明 |
|---|---|---|
| 收藏 (3 件套) | `addFavorite(id)` / `deleteFavorite(id)` / `isFavorite(id)` / `getFavorites()` | 强制统一,任何"喜欢/收藏/书签"业务一律用这套 |
| 访问计数 | `incrementVisitCount(id)` | 详情页 +1 |
| 危险等级 | `dangerousCount` (props) / `getDangerous(int minLevel)` | 按业务区分,物种用 `dangerousCount` |
| 总数 | `totalCount` (props) | `totalEntries` / `totalChecklists` / `totalTemplates` / `totalItems` / `criticalCount` → 全部统一为 **`totalCount`** (props) 或按业务分 (`criticalCount` 仅急救清单保留语义) |

### 1.3 写入操作返回值

| 操作类型 | 返回值 | 失败语义 |
|---|---|---|
| 写操作 (save/update/delete) | `bool` | `true` 成功 / `false` 失败 (Phase 5 切 Result) |
| 创建并返回 id (startTrack / createCustom / importXxx) | `QString` | 非空成功 / `""` 失败 (Phase 5 切 Result) |
| 查询列表 | `QVariantList` | 空 `{}` 表示无结果 (Phase 5 用 Result 区分"无结果"vs"失败") |
| 查询单条 | `QVariantMap` | 空 `{}` 表示未找到 |

### 1.4 业务独有方法

业务独有方法保留原名(如 `getEdible` / `getPoisonous` / `getMedicinal` / `getSnakes` / `getDeadly`),但禁止再起同义新名。

## 二、返回值类型语义

### 2.1 查询列表 (`QVariantList`)

```cpp
// ✅ 空列表表示"无结果"
Q_INVOKABLE QVariantList getByMonth(int month);   // 返回 [] 表示该月无数据

// ⚠️ Phase 5 升级: 区分"无结果"与"查询失败"
Q_INVOKABLE QVariantMap getByMonth(int month);   // {ok, value:[], error:{...}}
```

### 2.2 查询单条 (`QVariantMap`)

```cpp
// ✅ 空 map 表示"未找到"
Q_INVOKABLE QVariantMap getById(const QString& id) const;
// 调用方:
var entry = service.getById("xxx")
if (!entry.id) { /* 未找到 */ }
```

### 2.3 写入操作 (`bool`)

```cpp
// Phase 1-4: 返回 bool
Q_INVOKABLE bool saveRoute(const Route& route);

// Phase 5: 切到 QVariantMap (Result<T> 包装)
Q_INVOKABLE QVariantMap saveRoute(const Route& route);
// 调用方:
var result = routeService.saveRoute(route)
if (!result.ok) {
    Toast.error(result.error.message)
} else {
    Toast.success("已保存")
}
```

### 2.4 创建返回 id (`QString`)

```cpp
// 仅 4 处用此模式: MapService::startTrack / ChecklistService::createCustom / 
//                    MapService::importGpx / MapService::importKml
Q_INVOKABLE QString startTrack(const QString& name, int freqSec);
// 返回非空字符串 = 成功 (含 trackId), "" = 失败
```

## 三、QML 端调用规范

### 3.1 调用风格

```qml
// ✅ 推荐: var 接住返回值
var result = routeService.getById(routeId)
if (result && result.id) {
    page.route = result
}

// ⚠️ 可接受: 忽略列表结果(已知必返回)
listModel.clear()
listModel.append(routeService.getAll())

// ❌ 禁止: 不检查结果就解引用
page.route = routeService.getById(routeId)   // 空 map 会导致 undefined 字段
```

### 3.2 命名

| 类型 | 命名 | 示例 |
|---|---|---|
| Service 实例 | camelCase + Service | `plantService`, `routeService` |
| 方法返回值变量 | 业务语义命名 | `var route = routeService.getById(...)` |
| 列表变量 | xxxList / xxxModel | `var routeList = ...` |

## 六、与错误处理的衔接 (Phase 5 预览)

本规范定义的是 **接口层命名**,真正的"统一错误处理"需要配套 `src/core/Result.h` + `src/core/ServiceErrors.h` + `src/core/internal/QmlResultBridge.h`:

```cpp
// src/core/Result.h (Phase 5 落地)
template <typename T>
struct Result {
    T value{};
    ServiceError error;
    bool isOk() const { return error.isOk(); }
};

// 工厂
template <typename T>
inline Result<T> Ok(T v) { return {std::move(v), {}}; }

template <typename T>
inline Result<T> Err(ServiceErrorCode c, const QString& msg,
                     const QString& ctx = {}) {
    return {{}, {c, msg, ctx, {}}};
}

// QML 端通过 QmlResultBridge 自动转 QVariantMap
// 2026-09-21: 改 namespace + free function (旧 class + static 仍兼容 doc 写法)
QVariantMap toQVariant(Result<T> r) {  // 完整路径: outdoor::internal::toQVariant
    return {
        {"ok", r.isOk()},
        {"value", QVariant::fromValue(r.value)},
        {"error", QVariant::fromValue(r.error)}
    };
}
```

QML 调用方统一为:
```qml
var result = routeService.saveRoute(route)
if (result.ok) {
    Toast.success("已保存")
} else {
    Toast.error(result.error.message)
}
```

完整设计见 `doc/09-讨论记录/10-架构重构讨论.md` (Phase 5 部分)。

## 七、与设计模式的衔接

本规范约束接口层,设计模式约束实现层:

| 设计模式 | 应用位置 | 命名影响 |
|---|---|---|
| 策略模式 (Strategy) | `RuleConditionStrategy` (装备规则) | strategy 类统一以 `Condition` 结尾,如 `AltitudeCondition` / `PrecipitationCondition` |
| 工厂模式 (Factory) | `RuleConditionFactory` / `ServiceListModel` / `SpeciesServiceRegistry` | factory 类统一以 `Factory` 结尾 |
| 单例 (Singleton) | `Logger` / `App` | 单例类提供 `instance()` 静态方法 |
| 工具 namespace | `outdoor::internal` (含 `toQVariant` / `isOk` 等) | 2026-09-21 起, `QmlResultBridge` 由 class+static 改为 namespace+free function, service 内 `using namespace outdoor::internal;` 直接调用 |
