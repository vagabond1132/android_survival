### 修复 5:RecognitionEngine.initialize 错误被吞(P1-2)

**修改文件**: `src/core/App.cpp`

**修复前**:

### 修复 6:DecisionEngine 线程安全(P1-11)

**修改文件**: `src/firstaid/DecisionEngine.{h,cpp}`

**修复前**: `m_sessions` QHash 无锁保护,多线程并发调用会 race condition

**修复后**:
- `DecisionEngine.h` 加 `#include <QMutex>` + `mutable QMutex m_mutex`
- `DecisionEngine.cpp` 5 个 public 方法全部加 `QMutexLocker locker(&m_mutex);`(共 6 处,因为 `nodeToMap` 也加了)
- `QMutex` 是可重入的(同一线程可多次加锁),不会死锁

**应用场景**:
- QML 单线程:无影响(锁几乎无开销)
- 多线程(未来 QML 组件并发):安全保证

## 追加修复记录(2026-08-27 第四轮 — P2 真实风险)

### 修复 11:紧急联系人主状态事务回滚(P2-1)

**修改文件**:`src/firstaid/EmergencyService.cpp` `setPrimary()`

**修复前**:
```cpp
db.transaction();
q.exec("UPDATE ... is_primary = 0 ...");  // 失败不报错
q.exec("UPDATE ... is_primary = 1 ...");  // 失败不报错
db.commit();
```

**风险**:`is_primary` 是 SOS 短信群发的关键状态。两条 UPDATE 任一失败但事务仍 commit,会出现"0 个主联系人"或"多个主联系人"——影响实际救援。

**修复后**:`db.transaction()` 检查返回值;累计 ok 标志,任一 exec 失败回滚 + 日志;commit 失败也记日志。

### 修复 12:SOS 事件入库失败不再静默(P2-2)

**修改文件**:`src/firstaid/EmergencyService.cpp` `recordSosEvent()`

`q.exec()` 失败时记 `Logger::error(lastError)`,SOS 历史表丢数据时用户能感知。

### 修复 13:ncnn Tensor 失败返回明确错误(P2-3)

**修改文件**:`src/recognition/RecognitionEngine.cpp` `runInference()`

`ex.input(...)` / `ex.extract(...)` 检查返回值(原代码不检查),失败返回 `Status::UnknownError` + 具体错误信息。

### 修复 14:recognizeAsync 改用 QFutureWatcher(P2-4)

**修改文件**:`src/recognition/RecognitionEngine.cpp` `recognizeAsync()`

**修复前**:`QtConcurrent::run` + 立即 `future.result()` 同步等待 → 实际是同步,UI 卡死 1-3 秒。

**修复后**:`QFutureWatcher` 异步,完成后 `deleteLater()`,通过 `recognitionCompleted` 信号回调 QML。

**修复后**:
```cpp
auto count = [&](const QString& where) {
    QSqlQuery q(db);  // 每次 new 避免状态污染
    ...
};
```

- `EquipmentEngine.h` 末尾(namespace 外)加 `Q_DECLARE_METATYPE(outdoor::RecommendedItem)` + `QList<outdoor::RecommendedItem>`
- `FieldGuideHistory.h` 末尾加 `Q_DECLARE_METATYPE(outdoor::ViewRecord)`

### 修复 31:PermissionManager lambda UAF(P2)

**问题**:`PermissionManager::requestPermissions` 的 lambda 按引用捕获局部变量 `&remaining` / `&granted` / `&permissions`。Android 真实异步权限回调到来时,函数已返回,局部变量销毁 → UAF 崩溃。

**修复**(`src/platform/PermissionManager.cpp:44-68`):改用 `std::make_shared<SharedState>()` 值捕获,引用计数管理生命周期。所有 lambda 值捕获 `state`,直到所有 callback 完成 state 才销毁。新增 `#include <memory>`。

### 修复 32:ensureSchema 未检查 q.exec 返回值(P3)

**问题**:`EmergencyService.cpp` / `FirstAidService.cpp` / `SpeciesService.cpp` 的 `ensureSchema` 中 DDL `q.exec()` 失败被静默忽略,数据库 schema 可能不完整,后续 INSERT 才暴露问题。

**修复**:每个 Service 用 `execDdl` lambda 统一执行 + 检查 + `Logger::error`,失败用 `bool ok &=` 累积,返回 `ok` 让上层感知。`EmergencyService` 构造函数里 DDL 同样处理。
