## 变更公告：本轮 (2026-10-16 · 第十二轮 代码梳理 + 文档对账)

本轮不改功能,做的是"让文档重新可信 + 让测试真的能跑":

- **单测工程从未跑通 → 23 套件全部编译**:`tests/CMakeLists.txt` 原用项目根相对路径且缺
  `enable_testing()`,`cmake` configure 直接报 `Cannot find source file: src/core/Database.cpp`、
  `ctest` 报 `No tests were found`。现改为 `${APP_ROOT}` 前缀 + OBJECT 库(31 个 .cpp 只编一次),
  并把编译对象从已废弃的 `src/firstaid`/`src/emergency`/`src/platform/PermissionManager`
  切到线上真正打进 APK 的 `src/lifesaver`/`src/preparation`。
- **新增 4 个测试套件**:`test_asset_loader`(13 份 JSON 条目数对账)、`test_settings_store`、
  `test_checklist_service`、`test_map_service`(此前 45 个 Q_INVOKABLE 零覆盖)。
- **桌面单测镜像**:`Dockerfile.hosttests` + `docker-compose.yml` 的 `unit-test` service
  (原 APK 镜像的桌面 Qt 缺 `qtpositioning`,任何碰 `QGeoCoordinate` 的测试都编不过)。
- **死代码归档**:`.bak_deadcode_20261016/` 收 49 个文件/6,774 行(重构遗留的 firstaid/emergency
  旧副本、未接线的 Recognition*、零引用的 `DecisionEngine`、未注册的 QML 页面与组件)。
- **QML 唯一运行期告警修复**:`HomePage.qml:226` 退出时 `firstAidService` 已析构导致
  `Cannot read property 'totalEntries' of null`(run.txt 整份日志里唯一一条 QML warning),加 null 守卫。
- **AndroidPlatform 桌面可编译**:`getActivity()`/`kQtNativeClass` 收进 `#ifdef Q_OS_ANDROID`
  (此前桌面构建报 `QJniObject is incomplete`,而非 Android 分支仍要 `new AndroidPlatform()` 桩)。
- **文档对账**:所有统计数字改为脚本重新实测(见下表),并修掉 `H:\AI_Claude\work_dir\app` 这类
  早已不存在的开发机路径。

## 4. 文档同步规范

> **项目级强制规则**: 任何代码变更(新增/重构/修 bug/性能优化)后,必须同步梳理文档。
> 详见 [05-工程规范/文档同步规范.md](05-工程规范/文档同步规范.md)

- **位置**:所有项目文档都在 `app/doc/` 下
- **命名**:中文文件名,数字前缀表示**目录内顺序**
- **更新频率**:
  - 10-需求清单/需求清单与实现状态.md → 每次需求/数据变更时
  - 代码审查与测试报告.md → 每次修复 P0/P1/P2 时
  - 其他文档 → 模块变更时
- **新增文档**:先在对应目录的 `00-README.md` 注册,并更新 `00-文档总览.md`
- **删除过时文档**:合并到主清单后删除(参考 2026-08-27 整理:删除 audit.md,合并 06-工程规范/ 到 05-工程规范/)
