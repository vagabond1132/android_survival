## 一、逐条改了什么

### 1.1 L15：弹层正文必须有宽度约束（15 号 §四 那条「确认框正文比框还宽」）

裸 `Text` 挂 `ColumnLayout` 却不写 `Layout.fillWidth` 时，布局给子项的尺寸就是它的 `implicitWidth` ——
`wrapMode` 永远不触发，整句把 `Dialog` 撑到贴屏幕边、末字被裁。源码看着没毛病，**只有真机看得见**。

落点 7 个文件（`contentItem:` 与 `wrapMode` 同时出现的文件）：
`Main.qml` / `EmergencyContactsPage` / `EquipmentDetailPage` / `EquipmentPage` /
`FieldGuideDetailPage` / `MapPage` / `TrackDetailPage`。

判据口径写进新门禁 `dialog_text_width_check.js`：只认 `Dialog`/`Popup` 的 `contentItem` 子树
（`Button` 的 contentItem 由控件自己给宽，按同一条判会把 FilterRow / 底部导航那几格全骂成假命中），
按**最近父级**要求约束，反向坑（非 Layout 父级里写 `Layout.fillWidth` 是死的、`fillWidth: false`）也判。

### 1.2 L16：`kind` 与「不可撤」附注必须咬合（#56）

`DialogFooter.qml` 里 `confirmCode` 的默认值是 `kind === "danger" ? "不可撤" : ""` ——
「这颗键不可撤」本来只有一个来源。0.0.9 真机抓到两处写反：擦屏幕画线的「清空」标了不可撤，
真删存储的反而没标。写反一次就是**骗人按删除**，所以这条不是一次性修掉，是封成门禁：
C1 必须显式写 `kind`；C2 只许三个字面量档位；C3 非 danger 不许写非空 `confirmCode`；
C4 danger 不许写空串；`confirmCode` 写成表达式判「绕过档位单点」。
前置：`DialogFooter` 默认 `kind` 若被翻掉，门禁停判 `exit 2` 要人重新对齐全树。

### 1.3 L12 补条：错误通道两侧（用户选的 ②）

屏幕上「读不到: not found」这类短句**根本不在 qml 里** —— 它是 C++ service 用
`fail(ServiceErrorCode::X, msg, ctx)` 或 `Err<T>(...)` 塞进 `QVariantMap.error` 的，QML 端只是把它画出来。
原有的 `user_text_marks_check.js` 只扫 `qml/`，这条通道整个是盲区。

- **写入口两侧都封**：`fail(` 25 处 + `Err<T>(` 44 处 = **78 处**（第一版只封 `fail`，"0 条"是假绿）；
  另一族是 `requireNonEmpty/NonBlank` 的**字段名参数**（**9 处**，本轮其中 6 处原样是
  `"equipmentId"` / `"listMap.id"` / `"route.id"` 这种键名，屏幕上就是「equipmentId 不能为空」）。
- **英文串 → 中文**：detail（`file.errorString()`、驱动原文、id、路径）一律改道进 `Logger`，屏上只留中文短句。
  本轮改到的 service：`EquipmentService` / `EmergencyService` / `MapService_photos` / `MapService_species` /
  `MapService_tracks` / `ChecklistService` / `RouteService` / `TravelService` / `FieldGuideHistory` / `KnotService` /
  `SettingsStore`。GPX/KML/CSV 打不开那句以前是 `emit warningTriggered("无法打开文件: " + filePath)` ——
  整条路径直接端上屏，现在路径进 `Logger`，屏上是「这个 GPX 文件打不开」。
- **新规则 R5 / R6**（写完头四条才发现的洞）：R5 = message 表达式里 `.arg(标识符)` 且变量名像内部记号
  （`*Id`/`id`/`*Path`/`path`/`err`/`error`/`lastError`/`ctx`）—— 字面量写得再干净，`「清单不存在: %1」.arg(listId)`
  出来的还是 `user_1731746` 这种尾巴；带运算或取成员的（`.arg(int(code))` / `.arg(m["id"])`）静态分不清，**不骂**。
  R6 = 校验 helper 的字段名必须含汉字。**改完的实测口径**：全树 78 个写入点的 message 里 `.arg(` 现存 **0 处**、
  9 处字段名全部含汉字。
- **`dbErr` / `propagateError` 兜底**：`dbOpenCheck` 失败给「本机数据库没打开」；`propagateError` 只透传
  子调用已判过的中文文案，那里写了全树唯一一条豁免 `L12 免: …`（门禁查未 strip 的原文，偏移量等长对得上）。
- **头文件教学改了**：`QmlResultBridge.h` 的 `requireNonEmpty` 用法示例以前写 `"name"`，照抄就违规；
  现在示例是 `"这条装备的编号"`，`@param name` 写明「会被拼进屏幕上那句，必须写给人读的中文」。

### 1.4 删轨迹留幽灵选择（#55）

`MapService::deleteTrack` 以前只发 `tracksChanged`，地图页已经画出来的那条线不摘、选中态还在。
现在删除点名 `emit trackDeleted(id)`（[MapService_tracks.cpp:329](../../src/map/MapService_tracks.cpp)），
`MapPage.qml:1072` 的 `function onTrackDeleted(trackId)` 接住并 `removeTrack()`。
钉住它的测试：`tests/unit/test_map_service.cpp:206 test_deleteTrackEmitsTrackDeleted()`
（`QSignalSpy` 判「发了一次、带的就是被删的那条」）。

### 1.5 #43：详情页 hero 的返回方块收成一套几何（L13）

真机 0.0.9 量到 hero 家族把返回方块画成 **30 见方**、热区只外扩 **6**、上边线 **305**，
而页头带是 26 / 9 / 294 —— 同一族控件三种抄法。现在 12 处方块共用同一组 token
（边长 `styles.pageHeadBox`、热区 `anchors.margins: -styles.pageHeadTapPad`、上边线 `styles.spXs`、
右让位若写了则 `styles.pageMargin`），并进 `page_head_check.js` 成为**判据 ⑥**。

**先量后写**：形状是全树量出来的 —— `tmp_reg/corner_survey.js` 打出 44 个右上角组，其中正好
11 组（12 块：9 页 hero 各 1 块 + 图鉴 1 组 2 块 + 页头带 1 块）带 `IconLabel`，
其余 32 组（发丝线、错误行、布局列）都不带，所以判据不误伤。`--verbose` 现在把这 12 块的
`文件:行号` 全打出来 —— "0 处"因此可查，不是空口。

并排多块时另加一条：`spacing` 必须 ≥ 2×`pageHeadTapPad`。两格热区各外扩 9 px，间距 4 会让**后画的**
「返回」热区吃掉前一格（收藏）的右边缘 —— 图鉴页那两颗点不中收藏就是这么来的。

**包侧 C++ 文案反查**：`fail()`/`Err<T>()` 的字面量不进 rcc，编译进主 `.so` 的字符串表，所以 rcc 探针盖不到 L12 的 src 半。

must-hit `本机数据库没打开` 1 · `这个 GPX 文件打不开` 2（`warningTriggered` 与 `fail` 各一处）· `这条装备的编号` 1；

这条口径值得记一句：**QML 改动能靠 rcc 探针反查，C++ 改的文案必须另走 `.so` 字节**，否则"包侧已复核"只盖了一半。

*未做：把这段 `.so` 字节反查固化成 `tools/` 里的常驻脚本 —— 本轮是人判一次，下一轮改 src 文案时应当补成门禁。*
