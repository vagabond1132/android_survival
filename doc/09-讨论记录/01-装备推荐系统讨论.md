## 一、原始需求

用户提出：**根据行程、天气、海拔、路线难易程度，提供必须携带的物资装备列表，并支持自定义、增删记忆修订**。

## 二、讨论要点

### 2.1 功能分解

| 能力 | 描述 |
|---|---|
| 智能推荐 | 根据输入参数自动生成装备 |
| 完全自定义 | 增删任意装备 |
| 记忆 | 记住用户的选择和习惯 |
| 修订 | 基于反馈持续改进 |

### 2.2 输入维度讨论

| 维度 | 价值 | 状态 |
|---|---|---|
| 行程 | ⭐⭐⭐⭐⭐ 极高 | 保留 |
| 天气 | ⭐⭐⭐⭐ 高 | 保留（V1 用季节代替）|
| 海拔 | ⭐⭐ 低 | 简化为路线 |
| 难易度 | ⭐⭐⭐⭐⭐ 极高 | 保留 |



---

## 三、推荐算法讨论

### 3.1 方案选择

| 方案 | 优点 | 缺点 | 选择 |
|---|---|---|---|
| 规则引擎 | 透明、可控 | 规则需维护 | ✅ |
| 机器学习 | 个性化 | 黑盒、需数据 | ❌ |
| 混合方案 | 兼具两者优点 | 复杂 | ❌ V1 不做 |

### 3.2 规则示例

```
R1: 天数 >= 2 → 必带 [帐篷/睡袋]
R2: 海拔 >= 2500 → 推荐 [红景天]
R3: 难度 >= 4 → 必带 [头灯/急救包/绳索/刀具]
```

## 四、记忆与学习

### 4.1 记忆内容

| 类型 | 价值 |
|---|---|
| 个人偏好 | 喜欢用固体燃料 |
| 历史清单 | 一键复用 |
| 修改记录 | 推测下次 |
| 跳过记录 | 警告而非强制 |

### 4.2 记忆开关

- 可视、可编辑、可删除
- 关键装备（急救/求救）**永远不被记忆跳过**

---

## 五、增删修订流程

### 5.1 三种编辑模式

| 模式 | 影响范围 | 适用场景 |
|---|---|---|
| 仅本次 | 临时修改 | 一次性使用 |
| 记忆 | 影响未来 | 个人偏好 |
| 反馈 | 帮助改进 | 修正错误 |

### 5.2 用户路径

```
创建清单
  → 系统推荐
    → 用户修改
      → 选择：仅本次 / 记忆
        → 仅本次：直接保存
        → 记忆：保存到偏好
          → 下次自动应用
```

## 六、合理性质疑

### 6.1 已质疑的设计点

| 质疑 | 我的回答 |
|---|---|
| 推荐要"强制"到什么程度？ | 三档制（必带/推荐/可选）|
| 推荐算法会不会让用户带"过于齐全"？ | 提供精简/标准/保命三档 |
| 天气数据来源？ | V1 用季节，V2 加 API |
| "海拔"的价值？ | 简化为路线，不做海拔识别 |
| 学习 vs 干扰？ | 可关闭、可清除、有红线 |
| 装备库谁维护？ | 基础库+用户自建 |
