## 二、微调影响默认推荐

### 2.1 三种生效范围

```
A: 仅本次（默认）
B: 本次 + 记忆偏好
C: 升级段位
```

### 2.2 记忆数据模型

```cpp
struct UserPreference {
    QString id;
    QString userId;
    PreferenceType type;
    QString condition;   // JSON: 条件
    QString action;      // JSON: 动作
    int confidence;      // 0-100
    QDateTime createdAt;
    QDateTime lastUsedAt;
    int useCount;
};
```

### 2.3 优先级

```
1. 用户本次手动选择（最高）
2. 记忆偏好匹配
3. 系统规则推荐
4. 默认推荐（最低）
```

### 2.4 信心度算法

```
手动标记 = 100%
1 次自动应用 = 50%
5 次 = 75%
10 次 = 85%
20 次 + 显式确认 = 95%
```

## 三、装备检查表设计

### 3.1 检查表 vs 装备清单

| 维度 | 装备清单 | 装备检查表 |
|---|---|---|
| 目的 | 准备 | 出门核对 |
| 状态 | 编辑中 | 执行中 |
| 视图 | 卡片列表 | 复选框网格 |
| 完成度 | 可未完成 | 必须完成 |

### 3.2 三种模式

| 模式 | 用途 |
|---|---|
| 标准 | 出发前完整核对 |
| 精简 | 营地快速核对（必带）|
| 紧急 | 应急（只查急救/求救）|

### 3.3 状态指示

| 状态 | 颜色 | 含义 |
|---|---|---|
| ✅ 已确认 | 绿 | 勾选 |
| ❌ 未确认 | 红 | 未勾选 |
| ⚠️ 重要 | 橙 | 必带 |
| 🔒 锁定 | 灰 | 不可取消（如急救）|
| ❓ 不确定 | 蓝 | 标记疑问 |

## 四、PDF 导出设计

### 4.1 PDF 内容

```
封面
  - 行程名称
  - 日期
  - 路线缩略图
  - 用户头像/姓名（可选）

第一部分：路线信息
  - 路线详情
  - 海拔曲线
  - 关键点
  - 危险点
  - 救援电话

第二部分：装备清单
  - 必带
  - 推荐
  - 可选
  - 总重量

第三部分：检查表
  - 简洁复选框
  - 类别分组
  - 重量统计

第四部分：应急信息
  - SOS 流程
  - 急救电话
  - 紧急联系人
  - 路线救援
```

### 4.2 导出格式

- **A4 纸张**
- 适合打印
- PDF 文件
- 文件名：`路线名_日期_OS-装备清单.pdf`

### 4.3 分享方式

- 系统分享（Android Intent）
- 微信 / QQ / 钉钉
- 邮件
- 蓝牙
- 拷贝到 U 盘

## 五、数据存储设计

### 5.1 存储位置

```
所有用户数据 → 本地 SQLite
- 用户偏好（UserPreference）
- 装备清单（Checklist）
- 检查表进度（ChecklistProgress）
- 路线（Route）
- 历史记录（History）
```

### 5.2 存储期限

- **永久保存**
- 不自动清理
- 除非用户主动删除

### 5.3 备份方式

- 导出为 JSON 文件
- 手动备份到 U 盘 / 网盘
- 不上传云端（隐私优先）

## 六、特殊场景处理

### 6.1 "我没带急救包" 怎么办？

```
1. 红色警告
2. 弹窗确认"我确认不带"
3. 输入原因
4. 记录到历史
5. 频繁不带 → 下次主动提醒
```

### 6.2 "装备临时损坏" 怎么办？

```
1. 检查表标记"已损坏"
2. 系统建议替换方案
3. 添加到"装备维护提醒"
```

### 6.3 "多人队伍" 怎么办？

```
1. 领队一份"队伍总清单"
2. 每人一份"个人清单"
3. 自动避免重复
```

### 6.4 "孩子" 怎么办？

```
1. 子清单（儿童装备）
2. 额外药品
3. 更多保暖
```
