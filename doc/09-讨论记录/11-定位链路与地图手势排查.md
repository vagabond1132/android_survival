## 一、海拔 / 精度读数全空（#98）

### 现象

①营地与⑤求助两页的经纬度能出数，**海拔与精度一直是空**；SOS 短信里精度写成 `0 m`。

### 真因：Qt 的 Android 定位插件从来没有拿到 `Context`

`问题清单.md` A2 抄的 logcat 原文（决定性）：

```
W/qt.positioning.android: No locationManager available in QtPositioning
java.lang.NullPointerException: ... at
  org.qtproject.qt.android.positioning.QtPositioning.addActiveListener(QtPositioning.java:165)
  at org.qtproject.qt.android.positioning.QtPositioning.startUpdates(QtPositioning.java:208)
W/OutdoorDiag: GPS error: 2
```

容器里 `javap` 拆 `libplugins_position_qtposition_android` 对应的 Java 类看到的形状：

```java
public class QtPositioning {
    private static LocationManager locationManager;          // 只有这一个赋值口
    public static void setContext(Context ctx) { ... }       // ← 插件 C++ 侧从不调它
}
```

`locationManager` 是 **static**，只能由 `setContext()` 赋值；插件的 C++ 那边不叫这个方法，
`locationManager` 就是 `null`，`addActiveListener()` 一进来 NPE，往上冒成
`QGeoPositionInfoSource::UnknownSourceError`（枚举值 **2**）。
所以 error 2 刷了 79 次、`GPS source ready` / `GPS update started` 都在而
`GPS update: lat=` 一条都没有 —— 不是权限、不是系统开关、不是 provider 空。

### 修法

| 位置 | 改什么 |
|---|---|
| `android/src/com/outdoor/survival/OutdoorSurvivalApp.java` | `onCreate()` 末尾 `initQtPositioning(this)`：反射拿 `QtPositioning` 类 → `getMethod("setContext", Context.class).invoke(null, context)`，顺带打印 `getProviders(true)` 作为下次排查的第一行证据。`Application.onCreate()` 早于 Qt 库加载，所以插件任何一次调用之前这个静态字段已经有值 |
| `src/lifesaver/EmergencyService.cpp` | ①`requestLocationUpdate()` 开头补权限门 `if (!m_permGranted) { startLocationUpdate(); return; }`（巡检顺带②：原来这条路绕过权限门，冷启动没授权就直接建源）；②`onSourceError()` 按**真实枚举**翻中文（`AccessError 0 / ClosedError 1 / UnknownSourceError 2 / NoError 3 / UpdateTimeoutError 4`），走 `locationDiag` 给到人眼；③日志里 `availablePositioningMethods()` → `supportedPositioningMethods()`（Qt 6.7 没前者，编译期就炸） |
| `EmergencyService` 读数口径 | 精度与海拔用 **NaN 表示未知**，不用 0。`m_accuracy` 初值 `quiet_NaN()`（巡检顺带③：原来回落 0，UI 与 SQLite 都会把"没测到"读成"精度 0 m"）；`m_elevation = coord.altitude()`；拿到新定位就 `setDiag("")` 清掉原因 |
| SOS 短信 / 历史行 | 精度未知时写「精度：未知（只有坐标本身可信）」；海拔那一行只在 `std::isfinite()` 时出现。落库走 `std::isfinite(m_accuracy) ? QVariant(m_accuracy) : QVariant()` —— **REAL 列会把 NaN 静默变成 0**，未知必须存 NULL |
| JNI 签名 | `nativeUpdateLocation(long, double lat, double lon, double accuracy, double altitude, long time)` 补上 `altitude`（巡检顺带①：Java 的 `Location` 一直有 `getAltitude()`，之前桥只传 lat/lon/acc/time，走 SOS 前台服务这条路的海拔永远是 NaN）。Java 声明与 C++ 导出名逐项对齐，错一个参数就是运行期 `UnsatisfiedLinkError` |

同时**删掉**了自己写的 `android/src/com/outdoor/survival/LocationBridge.java` 和
`startJavaLocationBridge()` / `stopJavaLocationBridge()`。它的前提（"插件两条订阅都只回
error 2，得自建第二条 Java 通道"）是错的：真因是 `setContext` 缺失，补上之后 Qt 这条路
自己就通。留两条通道只会 last-write-wins 把精度好的读数覆盖掉。
`EmergencyService.java` 里的 `pushLocation()` 转发壳一并删除，两条订阅汇进同一个 native 方法。

## 二、地图手指推不动（#78）

### 为什么连着两轮"修完还是不动"

| 轮次 | 解掉的东西 | 留下没解的 |
|---|---|---|
| #43 | `center` / `zoomLevel` 的声明式绑定把视图锁死（每帧拖完被拉回） | 只是不拉回了 |
| #78 前半 | `TapHandler { gesturePolicy: ReleaseWithinBounds }` 按下即**独占抓握**，饿死地图（`QQuickPointerTapHandler::wantsGrab()` 里只有默认 `DragThreshold` 走 passive grab） | 只是不饿了 |
| #78 本次 | —— | **引擎本体一直没人补** |

真因：Qt 6.7 的 `Map` 类型**自己一个手势件都没有**。官方那个"可交互地图"
`QtLocation/MapView.qml` 就是在 `Map` 里面手写 `DragHandler` + `PinchHandler` 拼出来的。
观感完全对得上："手指拖不动，但 +/- 和程序改 `center` 都正常"。

### 落地（`qml/pages/MapPage.qml` 末尾，`Map` 块内）

照搬 `MapView.qml`：`target: null`、`onTranslationChanged: (delta) => map.pan(-delta.x, -delta.y)`、
`grabPermissions: PointerHandler.TakeOverForbidden`（否则长按标注会来打断捏合）、
捏合开始记 `startCoord`、`onScaleChanged` 里 `zoomLevel += Math.log2(delta)` 之后
`alignCoordinateToPoint(startCoord, centroid.position)` 让手指底下的地物不跑偏。
`toCoordinate(centroid.position, false)` 那个第二参数也是 Qt 原式，别删。

三样**故意没搬**，都不是嫌麻烦：

- **惯性动画**：要额外 `import Qt.labs.animation`。
- **`BoundaryRule on zoomLevel`**：`MapView` 靠它兜档位，但 `BoundaryRule` 就注册在
  `QtLabsAnimation`（`QtLabsAnimation/private/qquickboundaryrule_p.h` 里
  `QML_NAMED_ELEMENT(BoundaryRule)`），而**这个模块 Android Qt 安装目录里根本没有**
  （容器实测 `ls /opt/Qt/6.7.2/android_arm64_v8a/qml | grep -i labs` = 空），
  写进 QML 直接 `BoundaryRule is not a type`。offscreen 探针同时证实
  **`Map` 自己不夹档位**：`maximumZoomLevel: 18` 时赋 25 仍然是 25，越界档位的后果是
  去取不存在的瓦片层级 → 白屏，与 #14/#21 同一个观感。所以 `onScaleChanged` 里显式
  `Math.min/Math.max` 夹一次。另外两条写 `zoomLevel` 的路本来就夹过：
  `stepZoom()` 越界直接 return、`CommonOptions::fitBounds()` 用 `qBound(minZoom, z, maxZoom)`。
- **tilt / 两指旋转**：本页 `bearing: 0` 钉死正北（#98 那轮评审的截图就是正北朝上），
  让地图跟着罗盘转是另一件事，要先出稿。

### 两处抄错就会炸的地方（都是探针/门禁实测出来的）

1. `property QGeoCoordinate startCoord` → **加载期硬错误** `QGeoCoordinate is not a type`，
   整页白屏。`QtPositioning` 注册的是小写 **`geoCoordinate`**（`MapView.qml` 写的就是
   `property QP.geoCoordinate`）。这条 `qml_load_check.sh` 抓到了，9 道静态门禁全都没抓到。
2. `MapView` 的倍率轴原式带 `±1` 余量：
   `minimum = 2^(minZoom - zoom + 1)` / `maximum = 2^(maxZoom - zoom - 1)`。
   轴的中性值是 `1.0`，而地图**已经顶到档位边界**时 `minZoom - zoom + 1 = 1` →
   `minimum = 2`，把"两指刚按下还没捏"的 `1.0` 夹到 2 上，白跳一档、而且永远回不到那一档。
   本文件去掉那两个 `±1`，用 `2^(minZoom - zoom)` / `2^(maxZoom - zoom)`。JS 复算：
   带余量时 16 个起始档位里有 2 个（z=3、z=18）中性值被夹在外面、可达档位只剩 [4,17]；
   去掉余量后中性值恒在区间内、可达档位正好 [3,18]。取整造成的越界由上面那个显式夹取兜住。

## 三、①「盘上目标行后面的数据有问题」的真身（#82①）

`mapService.addSpeciesLocation()`（`src/map/MapService_species.cpp:47-51`）把
`dangerLevel` **写死 0**，注释自己写了"MapPage 端用 speciesId 反查"。而这条反查
（`_speciesCache` 命中 → 否则按类别/名称关键词估）**只接在地图圆点**的 `_lvl` binding 里；
`dialTargets`（盘上的点）和 `mapTargets`（「目标」Tab 的行）照读 `m.dangerLevel`，
于是同一条毒蛇：圆点红、盘上与列表灰。修法是抽出 `mapPage.dangerLevelOf(m)` 一个函数，
三处共读（`qml/pages/MapPage.qml`）。

排除掉的两种猜测（都是"看着像 bug"）：

- **方位/距离原点不一致**：`NearbyTab` 的路线行按 `root.currentLat/currentLon` 算，
  而宿主传进来的就是 `mapPage.viewLat/viewLon`（#61 那轮定的"盘心跟地图中心走"），
  与 `mapTargets` 同源，不是两套口径。

验证：把 HEAD 里那段内联 `_lvl` 求值体与工作树里新函数体都从**源文件文本**抠出来，
14 条用例逐一比（缓存未就绪/命中/蛇/蘑菇/蜂/蝎/蚂蚁/含"毒"/含"危险"/空记录…），

## 四、短信里的"时间："是发送时刻，不是位置时刻（#98 复盘补）

上一轮把海拔/精度接通之后，还剩一条更隐蔽的：`formatLocationMessage()` 里那句
`时间:2026-10-23 01:12:34` 用的是 `QDateTime::currentDateTime()`，也就是**发短信**的瞬间。
而 ①/⑤ 进来时如果没有实时读数，会用系统缓存的 `lastKnownPosition` 垫底
（`seedFromLastKnown()`）—— 那条坐标可能是**几小时前甚至几天前**测的。于是短信长成这样：

> 位置：39.908720, 116.397500
> 时间：2026-10-23 09:40:00   ← 发送时刻
> （坐标其实是昨天 18:12 测的）

搜救队会照着它规划接近方式，这比不发位置更糟。修法（`src/lifesaver/EmergencyService.cpp`）：

- `m_positionTime` 记下**这条读数**的测量时刻：Qt 定位走 `info.timestamp()`，JNI 那条走
  `QDateTime::fromMSecsSinceEpoch(time)`（Java 侧 `Location.getTime()` 本来就有，以前只是没接）。
- `positionAgeNote()`：拿不到时刻 → **不写**（宁可不写也不编一句"刚刚"）；2 分钟内 → 不写
  （第一颗定位本来就要十几到几十秒，阈值再低会把正常锁星延迟也标成旧数）；否则写
  `⚠️ 位置采于 08:12（已 147 分钟），不是实时位置`，跨天改成 `MM-dd HH:mm` + 天数。
- 这一行拼进 `accuracyPart` 尾部而不是新开一个 `%n` 占位符 —— 否则不旧的时候短信里会多一个空行。
  `SOSPage` 的"复制位置"用的是同一个函数，所以两处口径天然一致。

## 七、蓝点没有朝向、精度停在粗值（2026-10-26 #129 批次）

用户实测：「导航栏地图 个人位置原点无方向指示，移动不能实时变化，同时右上方方位数据未变化」，
并单独要求「对 1 米量级精度直接修改代码」。

### 朝向：根因是"只有一个来源"，不是"罗盘坏了"

蓝点的楔形和右上角方位盘都只读 `compassSensor`。这台 Magic5 整轮巡检 QCompass 没出一条
有效读数（`azimuth` 恒 NaN），于是两处一起变成"没有方向 / 数字不动"。
关键点是：**人一走起来，GPS 是有航向的**。`QGeoPositionInfo::Direction` 就是 Android
`Location.getBearing()`（运动方位角，静止时 NaN/不可用），此前从未接出来。

- 新增 `EmergencyService::currentCourse`（`Q_PROPERTY`，NaN = 这一帧没给/静止）。
- 页面口径合成一条链：`effHeadingDeg` / `hasEffHeading` = **罗盘 > GPS 航向**，两者都无 →
  楔形整块不画、`relativeWord()` 退回绝对 8 方位，`headingNote` 写明这次用的是哪个来源。
  绝不给 0°——那等于谎报正北。
- `Dial.hasFix` 踩过一次语义误用：它管的是"有朝向来源才画指针"，把位置有效性喂进去会画出
  一根假正北。改喂 `hasEffHeading`。
- `CompassSensor` 原来只在"无硬件"和"start 失败"时说话，"硬件在、start 成功、reading 一直
  不来"这条缝完全静默。补了首帧/无效帧/读数恒定三条诊断（release 包 logcat 为空 → 进
  `stage0.log`），下一轮真机才分得清是哪一种。

### 精度：1 Hz + 静止多帧平均，但报出的 ± 只能报实测的那个数

原来 Qt 定位源 10 s 一个点，静止时根本攒不出可平均的帧。改成 `setUpdateInterval(1000)` +
优先 `SatellitePositioningMethods`，再在 `averageFixes()` 里做窗口平均（≤8 帧 / 6 s /
只有 ≤15 m 的帧进池 / 与池内最好点距离超过 `max(3 m, 那个 ±)` 就清池）。

**没有**把报出的精度写成理论 `σ_mean = σ/√N`。1 Hz 的 GNSS 帧高度相关（同一批卫星、
同一星历），√N 那个乐观没有硬件依据，报出来就是假读数——报池子里最好那一帧
**自己量出来的** ±。走动时静止条件不成立 → 清池退回单帧，平均绝不能把轨迹点拖在人身后。

覆盖判据（"精度显示上不去"的真因）：`acceptLocation()` 是 Qt 源与 Java 桥唯一的落库口，
手里的点还在 60 s 保鲜期内时，无 ± 或差 1.5 倍以上的来帧不许覆盖。

> 单测把这条写反过一次：新写的断言假设"没有 ± 且时间戳较旧的来帧"会被接受，实现拒绝了。
> 查下来是**判据看的是手里那点的年龄，不是来帧的时刻**——实现是对的。测试拆成 A（保鲜
> 期内 → 拒收）与 B（把手里的点老化到 120 s 前 → 接受）两段，各自成立，代码没改。
> 这正是"不给假读数"那条口径，与"不含"断言必须配对"含"断言的老问题。

### 逐点精度落库 + 界面不再编数

`addTrackPoint(trackId, lat, lon, elevation=NaN, accuracy=NaN)`、
`addSpeciesLocation(..., altitude=NaN, note, accuracy=NaN)`：未知的键整条不写（不是写 0，
也不是写 -1 —— `-1` 会被 `isfinite` 放行、落成"海平面 -1 米"）。
`getTrackStats` 放出 `hasAltitude` / `accuracyPointCount` / `accuracyAvgM` / `accuracyBestM` /
`accuracyWorstM`，界面据此决定整行画不画。
文案层还有三处自己会编数，一并撤掉：`TrackDetailPage` 表头写死"六格"（纯 2D 轨迹没有那
三行高程 → 改为 `statRows.length + " 项读数"`）、`RouteSummaryPanel` 未知时画"— m"（那枚
`m` 让格子看着像"单位已知的测量" → 单位一并撤）、各页把 ±0 当合法值显示（→ `isFinite(v) && v > 0` 才成行）。
