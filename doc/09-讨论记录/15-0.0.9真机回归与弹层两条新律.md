## 三、本轮新发现（四条，均待统一修改）

### 3.1 新律候选 L15：Dialog 正文 `Text` 不绑 `width` ⇒ `wrapMode` 是死的

**现象**（真机实测，`删除这条轨迹?` 确认框）：

```
卡片（Dialog）      设备 x 109..1117   = 360 逻辑 px
正文那一行墨迹      设备 x 145..1115
⇒ 左内边距 36 设备 px（12.9 逻辑），右内边距只剩 2 设备 px（0.7 逻辑）
⇒ 正文只有一行（墨迹带 y 1326..1355，高 30 设备 px ≈ 10.7 逻辑 = fsMd）
⇒ 句尾「删完找不回来。」整段被裁掉，屏幕上句子以逗号结束
```

**根因**：[TrackDetailPage.qml:890-897](../../qml/pages/TrackDetailPage.qml) 写了
`wrapMode: Text.WordWrap`，但 `Dialog` 的 `contentItem` 是裸 `Item`，**不会把宽度传给子项**；
没有 `width` 绑定也没有 `Layout.fillWidth` 的 `Text` 直接吃 `implicitWidth`，
于是单行铺满并溢出卡片右缘，`wrapMode` 全程没生效过。

**全树家底**（脚本：大括号配平找 `Dialog {` 块 → 块内 ±8 行窗口无 `width:` / `Layout.fillWidth: true` 的 `wrapMode`）：

| 文件 | 行 |
|---|---|
| `qml/pages/EmergencyContactsPage.qml` | 648 |
| `qml/pages/EquipmentDetailPage.qml` | 755 |
| `qml/pages/FieldGuideDetailPage.qml` | 1616 |
| `qml/pages/FieldGuideDetailPage.qml` | 1647 |
| `qml/pages/MapPage.qml` | 2017 |
| `qml/pages/MapPage.qml` | 2332 |
| `qml/pages/TrackDetailPage.qml` | 896 |

**共 7 处**。门禁判据建议：`Dialog` 块内出现 `wrapMode:` 的 `Text`，必须在同一块内拿到
`width:` / `Layout.fillWidth: true` / `contentWidth` 三者之一，否则报。
**注意反证**：`MapPage.qml:2017` 那张是「已选清单」，正文短所以肉眼看不出溢出 —— 门禁要按结构判，不按长度判。

### 3.2 新律候选 L12 补条：C++ 英文错误串直接拼进用户文案

真机 `轨迹 11-05 09:19` 详情页整页只剩一句：

```
统计没算出来: too few points
```

来源链：[TrackDetailPage.qml:193](../../qml/pages/TrackDetailPage.qml)
`trackDetail.note = "统计没算出来: " + (stats.error || "未知错误")`，
而 `stats.error` 是 C++ 侧的英文原文（[MapService_species.cpp:271 / :468](../../src/map/MapService_species.cpp)、
[MapService_tracks.cpp:137](../../src/map/MapService_tracks.cpp) 三处写死 `"too few points"`）。

这正是 #41 / L12「面向用户文案去内部记号」那一类，但**上一轮收的是中文内部记号（①-⑩、H50 S80 V70），
漏了"错误通道"这条**：只要把 `Result.error` 往用户可见串里拼，就把英文实现细节端出去了。

附带一条布局问题：该页统计失败后**正文区整片空白**，没有空态引导（对比「轨迹」Tab 的
`还没有轨迹` 空态是有图标+标题+引导句的）。空态口径不统一，也记进统一修改。

### 3.3 新缺陷：删除已加载的轨迹后，选择态留下幽灵项

实测序列（全程只碰本应用）：

1. 「轨迹」Tab 1 条 → 点行加载 → 行右侧出现橙色「已加载」，地图移到该点，浮层出现「已选 1」；
2. 点分析图进 `TrackDetailPage` → 「删除这条轨迹」→ 确认框「删除」；
3. 回到「轨迹」Tab：计数正确变成 **0 条**，空态 `还没有轨迹` 正常显示；
4. **但地图上的「已选 1」浮层还在**；点开它，里面仍然列着
   `▲ 轨迹 11-05 09:19 / 轨迹 · 1 个点`，而且**分析图与 × 两颗按钮都可点**；
5. 「清空」按钮此时也是**可用态**（黑图标），而它按下去清的就是那条已经不存在的轨迹。

即：**删除只动了存储，没动 `selectedTrackIds` / `trackOverlays`**。
对幽灵项点分析图会拿一个死 id 进详情页。这与 `MapPage.qml:2714` 那条注释里已经警惕过的
「变成一个只能靠『全部清空』收拾的幽灵项」是同一族，只是这次是删除路径触发的。

清理路径实测可用：「已选 1 项」→「全部清空」→「清空已选?」→「清空」，浮层消失、
「清空」按钮回到禁用态。存储侧无需再动（0 条）。

### 3.4 新缺陷：同一个视图操作，一处标「不可撤」一处标空

- [MapPage.qml:2096-2101](../../qml/pages/MapPage.qml) `selectedListDialog` 的 footer
  写 `confirmCode: ""`，注释明确：「清空选中只是视图状态，重新点一行就回来了 —— 不写『不可撤』的附注」；
- [MapPage.qml:2334-2337](../../qml/pages/MapPage.qml) `confirmClearDialog` 的 footer
  却写 `confirmCode: "不可撤"`，而它 `onConfirm` 调的是
  [`clearSelections()`](../../qml/pages/MapPage.qml#L3051) —— 纯数组置空，**同样只是视图状态**。

真机两张框都拍到了：第一张「全部清空」无附注，第二张「清空」带「不可撤」。
同一个动作从两扇门进去，对不可逆性的承诺相反。归 L12 口径类。
